# Glossary

The glossary is the shared-language layer. Reading it is not this skill; changing it is.

- **Challenge drift**: "the glossary defines X as …, but you seem to mean Y — which is
  it?"
- **Sharpen overloads**: two concepts sharing a word get two terms; two words for one
  concept collapse to one, with an `_Avoid_:` list for the losers.
- **Update inline as terms crystallize** — don't batch glossary edits to the end.
- Entry format: `**Term**:` one-to-two sentence definition, optional `_Avoid_:` list.
  Be opinionated. Project-specific terms only — never general programming concepts.
- **Zero implementation details.** The glossary is not a spec, a scratch pad, or a
  decision record. It is a glossary and nothing else.

Glossary edits are plan edits: they happen only inside a plan-editing skill (`/align`,
`/propose-change`, `/pivot`) whose session marker is set — the plan-gate hook enforces
this.
