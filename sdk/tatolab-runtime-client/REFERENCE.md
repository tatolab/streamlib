# Tatolab runtime control API

Generated by `cargo xtask generate-runtime-client` from `contract.json`, contract version 3 revision 41. Every method is a JSON-RPC 2.0 method on the runtime's local API socket: one request per `POST /control`, or one message per text frame on a WebSocket opened at `/control/ws`, which also carries notifications.

## asset

### `list_assets`

List a project's assets, ordered by path.

List a project's assets, ordered by path: each by its `asset` UUID, its `kind` (`stream`, `media`, `scene` or `data`), its `path` in the project, the SHA-256 and size of its bytes, its `import_settings`, and what the runtime has read from its bytes — `media_facts_state` (`read`, `reading`, `unreadable` with `media_facts_unreadable_because`, or `null` for a stream), `media_facts` and `preview`, as `describe_asset` answers them, each from what is already read, an asset not yet read queued for a read — with the project's UUID, `project_name`, `project_description`, `project_cover` — the UUID of the image asset it is shown by — and `project_last_edited_at`, when its history last changed in seconds since the Unix epoch, each `null` when it has none, and `transactions_resource_uri`, its change feed. `kind` narrows to one kind. Refused for a folder with no `tatolab-project.json`.

- Since contract version 1, stable.
- Params: `ListAssetsRequest`
- Result: `ListAssetsToolResult`
- Errors: `1` refused, `2` failed, `-32602` params do not match, `3` contract mismatch

Example params:

```json
{
  "project_directory": "/home/ada/Tatolab/night-show",
  "kind": "media"
}
```

### `describe_asset`

Describe one asset of a project.

Describe one asset of a project: its UUID, kind, path, the SHA-256 and size of its bytes, its import settings, `file_at_its_path`, whether a file is at its path, and what the runtime has read from its bytes, which it reads once per SHA-256 after an import or a replace and keeps in the project's `.tatolab/`. `media_facts_state` is `read`, `reading` — a read queued or under way, after which the project's change feed carries a `media_facts_read` entry — `unreadable`, with why in `media_facts_unreadable_because`, or `null` for a stream asset. `media_facts` carries `duration_ms`; `video` with `pixel_width`, `pixel_height`, `frames_per_second` and `codec`; `audio` with `sample_rate_hz`, `channel_count` and `codec`; `image` with `pixel_width` and `pixel_height`; `lut` with `lut_1d_size` or `lut_3d_size`, `domain_min` and `domain_max`; and `scene` — each `null` when the file does not hold or state it. `preview` is the size and `media_type` of the picture `read_asset_preview` answers, `null` when the asset has none.

- Since contract version 1, stable.
- Params: `DescribeAssetRequest`
- Result: `DescribeAssetToolResult`
- Errors: `1` refused, `2` failed, `-32602` params do not match, `3` contract mismatch


### `read_asset_preview`

### `import_asset`

Import a file as a new asset of a project, as one transaction.

Import a file as a new asset of the project at `asset_path`, or, with no `asset_path`, in its kind's folder of the project's standard layout — `media/` for video, audio and images, `scenes/` for USD, glTF and other 3D scenes, `data/` for everything else — under `file_name` or the source file's own name, numbered `<name>-2.<extension>`, `-3`, … past a name an asset or another file already takes there. Answers the `asset`, with the UUID the runtime made for it, which every later relocation keeps, and the `path` it landed at, and the `transaction` and `commit` that record it. The bytes are copied once, to `asset_path`, and only the asset's sidecar, `<asset_path>.asset.json`, enters history. `source` is a file on this machine by absolute path, copied there, or an upload in the project's `.tatolab/uploads/` by its SHA-256, moved there; a file already at `asset_path` is imported in place. Undoing the import removes the file at `asset_path`, one imported in place included, and nothing keeps its bytes. Refused whole, with nothing written, for a path another asset or another file holds, a path outside the project, and a stream, which is never imported.

- Since contract version 1, stable.
- Params: `ImportAssetRequest`
- Result: `AssetTransactionToolResult`
- Errors: `1` refused, `2` failed, `-32602` params do not match, `3` contract mismatch

Example params:

```json
{
  "project_directory": "/home/ada/Tatolab/night-show",
  "source": "/home/ada/Videos/opening.mp4",
  "asset_path": "media/opening.mp4"
}
```

## dependency

### `add_dependency`

Import another project into a project, as one transaction.

Import another project, as one transaction by `author`: the project `source` holds, a folder or a `.zip` of one on this machine, is copied whole into `imports/<folder>/` and recorded in `tatolab-project.json` under `dependencies` with the `version` its copy carries, the SHA-256 over its files. Nothing reaches the network. The copy is this project's own from then on: its assets are referenced as `{"asset": "<uuid>", "from": "<project uuid>"}` and read from its folder, its streams are placed with `use_dependency_stream`, and to edit it, open `imports/<folder>/` as a project of its own. Answers the `dependency`. Once it applies, a project with a `pyproject.toml` has its `.venv` made current on its stream action queue, a `make_venv_current` action that touches no stream, and its change feed carries `venv_made_current` once that is done, so the node types its imports install list. Refused, nothing copied, for a source holding no `tatolab-project.json` or no project UUID in it, naming what is missing, for this project itself, a project already imported, or a folder already held.

- Since contract version 1, stable.
- Params: `AddDependencyRequest`
- Result: `DependencyTransactionToolResult`
- Errors: `1` refused, `2` failed, `-32602` params do not match, `3` contract mismatch

Example params:

```json
{
  "project_directory": "/home/ada/Tatolab/night-show",
  "source": "/home/ada/Tatolab/stage-looks"
}
```

### `connect`

Link an output port to an input port in one loaded stream, as one transaction.

Link an output port to an input port in one loaded stream, as one transaction, each end a node's UUID and a port name `graph` lists under that node's `ports`. A stream reads another stream's track at a relay through a `MoqTrackReceive` node. A link is spliced in by connecting a new node on both sides, then disconnecting the link it replaces — or all three in one `transact`. A link that would close a loop of function nodes with no `tatolab.stream:PreviousValue` node in it adds one and runs through it: the result names it under `added_nodes`, with its `node_type` and `inserted_because` `closes_a_loop`, and both of its links under `connected_links`. A link whose two pin types connect only through one built-in conversion, such as a Texture into a Tensor, adds that convert node in the same edit, collapsed, holding the settings it picks for the input, and runs through it: the result names it under `added_nodes` with `inserted_because` `converts_pin_types`; one `undo` removes the node and both links. Each `connected_links` entry carries the `free_conversion` and `warnings` its link gets. Two ends that both state a pin type connect when the input takes what the output sends: the same type; a Texture whose every pixel format is one the input lists, an input listing none taking any, and an output listing none connecting to an input that lists some; an encoded video or audio stream or an Asset whose every codec or media is one the input lists, an input listing none taking any, and an output listing none connecting only to an input that lists none; a Menu into a Menu, whatever options each lists; or a type the input reads from the output's for free: Boolean, Integer and Float among themselves, a Vector into a Vector or a Color, one number into a Vector or a Color, a Menu into a String. Any other pair is refused with `link_pin_types_do_not_connect`, naming both types and either the node or nodes to place between the two ends or that no node type converts between them. A pair that only a conversion an installed module or the project's own node declares bridges is refused with `link_needs_a_module_conversion`, naming each such node type; with exactly one, `suggested_call` is the `transact` that places it between the two ends, only when both ends are UUID-named nodes the edited level holds. A link a saved graph document already holds that these rules refuse is kept when the stream loads, as long as its two ports carry the same kind of message, and the runtime logs the refusal. A setting read at setup takes a link from an output that flows as a `value`: once the stream has started, each value the link carries that differs from the one the node was built with rebuilds the node once, a burst of them arriving within about 50 ms of the first rebuilding it once with the last, and a node started while the link has carried one, its source's value as that source set up among them, is built with it; a value its node refuses to rebuild with is logged, and the node is rebuilt with the value it held before. A link into it from an output that flows as a `stream` or a `trigger` is refused with `link_streams_into_a_setting`, saved or not: place a node that samples it into a value between them, or set the setting's value with `set_node_input_value`. A link into a setting read each run, into a setting of a type no message carries, or into a setting of a `GraphInput`, `GraphOutput`, `SetVariable` or `GetVariable`, is refused with `input_takes_no_wire`. A function or shader node's output that flows as a `value` feeds a setting read at setup as any other node's does. Whatever evaluates a function node outside an island works its value out as it sets up, before the setting's node is built: the stream's function node pool, or the helper of its own a stateful node several nodes read runs in. The setting's node is built with that value at the start, and each value worked out after that which differs rebuilds the node as above. A shader node's output is a texture, which flows as a `stream`, so a link from it into a setting is refused with `link_streams_into_a_setting`. `graph` says under each input's `takes_a_wire` whether a link may end at it by these rules. These rules judge a link inside a placed stream, under a non-empty `level`, the same way, among the nodes of that level alone, by the settings each holds and the links the level holds, and judge each link a `PreviousValue` node closing a loop there is linked by; `connect` places no convert node there, so a link that needs one is refused naming it. A link there reaching a fragment node, a `GraphInput` or `GraphOutput` that does not yet say what it carries, or a node whose type is not described is saved unjudged, and its entry under `connected_links` says why under `not_judged_because`.

- Since contract version 1, stable.
- Params: `OneLinkGraphEditRequest`
- Result: `GraphTransactionToolResult`
- Errors: `1` refused, `2` failed, `-32602` params do not match, `3` contract mismatch

### `write_studio_view_output`

Write a value a Tato Studio view produced onto its node's output port. Replaced by `set_node_input_value`.

Hand a value a Tato Studio panel wrote to the view node `node` of the stream `stream`, which publishes it on its output `port` to every link and viewer reading that port, stamped with stream time now. A view node is a node of a view type, `<project name>:<view folder>`, which each view of the stream's project or of one of its imports is when it opens and its `placement` is `node`; its ports are the view's declared inputs and outputs, and a panel reads its inputs with `open_viewer` on the port linked into each. Each Array, Channels or Records output of a view node has an input of its name, a setting read each run that takes no wire and holds no saved value, whose value the node publishes on the output; this call sets that input. Every write is published, stamped with stream time now, the same value written again as much as a new one, a Channels block starting where the last one written ended. A write is live data: the last value written is what a reader keeps, and a reader that connects later reads it, many panels may write one node and the last write wins, nothing is recorded in the graph document or the project's history, and the input returns to no value at Stop; a saved value on that input, by a `commit` set or an `add_node`'s `pins`, is refused, and one a graph document holds is dropped as the stream loads, with a warning naming the node and the input. `graph` renders the value as the input's live value. An Image or Packets output, which has no such input, is refused. Refused for a stream whose project is stopped, naming `start_playback`; a node of another type; a node that is not running; a node with no such output; `null`, which sets no value; and a value its port's family does not take, as `input_value_not_valid` at `/value`. A refusal because the node does not run comes with `structuredContent.refusal.not_running_because` naming why: `playback_stopped`, `playback_paused` (a node added while its project is paused), `preparing` or `node_failed`, the runtime's words beside it in `runtime_words`. Replaced by `set_node_input_value`, which this call is one `live` set of, naming the view node as `node` and the output as `input`.

- Since contract version 1, stable.
- Params: `WriteStudioViewOutputRequest`
- Result: `WriteStudioViewOutputToolResult`
- Errors: `1` refused, `2` failed, `-32602` params do not match, `3` contract mismatch

### `write_graph_input`

Write a value onto one of a loaded stream's graph inputs. Replaced by `set_node_input_value`.

Hand a value to the Input `input` of the stream `stream`: the stream's top-level `GraphInput` declaring it publishes the value on its `value` output to every node it is linked to, stamped with stream time now, and each reads it on its next process; every write is published, the same value written again as much as a new one, and a node linked later reads the last value set. A write is live data: many clients may write one Input and the last write wins, and nothing is recorded in the graph document or the project's history. An Input whose config's `lifetime` is `kept`, the default, keeps the last value in the project's store, so it carries it again after a Stop, a reload and a restart of the runtime; a `reset` Input returns to its saved value, its `default`, at Stop. While the project is stopped, a `kept` Input takes the value and carries it at the next Play, and `graph` shows it; a `reset` Input is refused as `playback_stopped`. Until a write, the Input carries its saved value, if it holds one. `graph` renders the value an Input carries now, or carries at the next Play while stopped, under its node's `graph_interface` component, as `current_value`. Array, Channels and Records Inputs are written; an Image or Packets Input runs nothing and is refused. Refused for an Input no top-level `GraphInput` declares, and a value its family does not take. A refusal because the Input's node does not run comes with `structuredContent.refusal.not_running_because` naming why: `playback_stopped`, `playback_paused` (a node added while its project is paused), `preparing` or `node_failed`, the runtime's words beside it in `runtime_words`. Replaced by `set_node_input_value`, which this call is one `live` set of, naming no node and the Input as `input`.

- Since contract version 1, stable.
- Params: `WriteGraphInputRequest`
- Result: `WriteGraphInputToolResult`
- Errors: `1` refused, `2` failed, `-32602` params do not match, `3` contract mismatch

## Notifications

### `project_changed`

A change on the feed of a project the connection subscribed to: a transaction applied, an action refused, media facts read, its venv made current, node types it offers added, removed or updated, or files in its folder changed.

- Sent after `subscribe_project_changes`.
- Since contract version 1, experimental.
- Params: `ProjectChangedNotificationParams`

### `stream_graph_changed`

A change in the live graph of a stream the connection subscribed to: an edit, a node's new state, a playback change, new drops, raises or link states, or `missed`.

- Sent after `subscribe_stream_graph_changes`.
- Since contract version 2, experimental.
- Params: `StreamGraphChangedNotificationParams`

### `input_value_changed`

The value an input of a stream the connection subscribed to reads changed, set live or saved, with the `value` and `value_comes_from` `graph` renders for it; sent at most once each 33 ms for one input, ending on the last value.

- Sent after `subscribe_input_value_changes`.
- Since contract version 3, experimental.
- Params: `InputValueChangedNotificationParams`

### `stream_action_changed`

A stream action changed, which `describe_stream_action` describes, or `missed`.

- Sent after `subscribe_stream_action_changes`.
- Since contract version 2, experimental.
- Params: `StreamActionChangedNotificationParams`

### `project_log_records_written`

The new records of a project's log the connection subscribed to, with the cursors they follow and end at.

- Sent after `subscribe_project_log_records`.
- Since contract version 2, experimental.
- Params: `ProjectLogRecordsWrittenNotificationParams`
