# Tatolab runtime control API

Generated by `cargo xtask generate-runtime-client` from `contract.json`, contract version 1. Every method is a JSON-RPC 2.0 method on the runtime's local API socket: one request per `POST /control`, or newline-delimited messages on a connection upgraded at `/control/stream`, which also carries notifications.

## graph

### `transact`

Apply operations on one project's stream graphs as one transaction, whole or not at all.

Apply operations on the graphs of one project's loaded streams as one transaction by its `author`: applied in order, whole or not at all, to each running stream, and with `mode` `commit`, the default, written to each stream's graph document and recorded as one commit on the project's history, which `undo` reverses as one. Answers `mode`, the `transaction` and `commit` recording a committed edit, each operation as applied, `added_nodes` with each new node's UUID and the name it took, and `connected_links` with each new link's `state` — `pending`, `wired`, or `error` with its `error_reason`. Refused whole, in the runtime's own words, with nothing changed. A config value `{"asset": "<uuid>"}` must name an asset the project holds. An `add_node` may give its node an `as`, which later operations of the same transaction name the node by. The transaction is announced on the project's change feed, the resource `list_assets` names as `transactions_resource_uri`.

- Since contract version 1, stable.
- Params: `TransactRequest`
- Result: `GraphTransactionToolResult`
- Errors: `1` refused, `2` failed

### `add_node`

Add a node to a loaded stream's graph by its type's import path, as one transaction.

Add a node to a loaded stream's graph by its type's import path, as one transaction, the runtime making the node's UUID. A Python type is named `module:QualifiedClassName` and must be importable by the stream's own interpreter — a module in the stream's project, or a package installed in its venv: the runtime never imports it, and describes it in that interpreter the first time it is added; each add spawns it in its own processor interpreter, which imports the module fresh. The type's port declaration is read when it is first described and kept; to change a type's ports, add it under a new class name.

- Since contract version 1, stable.
- Params: `AddNodeRequest`
- Result: `GraphTransactionToolResult`
- Errors: `1` refused, `2` failed

### `connect`

Link an output port to an input port in one loaded stream, as one transaction.

Link an output port to an input port in one loaded stream, as one transaction, each end a node's UUID and a port name `graph` lists under that node's `ports`. A stream reads another stream's track at a relay through a `MoqTrackReceive` node. A link is spliced in by connecting a new node on both sides, then disconnecting the link it replaces — or all three in one `transact`.

- Since contract version 1, stable.
- Params: `OneLinkGraphEditRequest`
- Result: `GraphTransactionToolResult`
- Errors: `1` refused, `2` failed

## observe

### `discover`

Answer the contract version this runtime serves, its version and build id, and every method it serves.

Answer `contract_version`, the version of the contract this runtime serves, its `runtime_version` and `build_id`, and `operations`, every method it serves. A client sends the `contract_version` it was built against; another version is refused naming both, and the client is not served.

- Since contract version 1, stable.
- Params: `DiscoverRequest`
- Result: `DiscoverResult`
- Errors: `1` refused, `2` failed, `3` contract version mismatch

### `describe_runtime`

Describe this runtime: its version, its build id, how long it has been up and where it logs.

Describe this runtime: its crate `version`, its `build_id` (`<version>+<git sha>.<per-build nonce>`, telling two builds of one version apart), `up_for_ms`, the monotonic milliseconds since its engine started — a restart resets it — and `runtime_log_directory`, the folder its own log is written to, `null` when it keeps none. Names no stream.

- Since contract version 1, stable.
- Params: `DescribeRuntimeRequest`
- Result: `DescribeRuntimeToolResult`
- Errors: `1` refused, `2` failed

### `graph`

Export a loaded stream's live graph, or every loaded stream's, with each node's and link's state.

Export a loaded stream's current graph as JSON: the stream it was loaded as, its nodes by name with their types, config and ports, its links by node and port, with each node's and link's live state and counters beside them, and this machine's name (`machine`), the first part of `<machine>/<stream id>/<node>/<port>`. A fragment — a graph generator's stored output — renders as one node of `kind` `fragment` whose ports are its Graph Input and Output nodes' and whose `fragment` holds its own nodes and links, a fragment inside it rendered the same way; its nodes run under their path of names, `look/soft/blur`. Without `stream`, `{machine, streams}` holds every loaded stream's graph.

- Since contract version 1, experimental.
- Params: `GraphRequest`
- Result: `unknown`
- Errors: `1` refused, `2` failed

## project

### `subscribe_project_changes`

Send this connection a `project_changed` notification for each change on the named projects' feeds.

Subscribe the connection to the change feeds of `projects`, by UUID: from then on, each transaction applied to one, each action the runtime refuses on one and each media facts read it finishes is sent as a `project_changed` notification, whoever made it, until the connection closes. Served only on a connection that stays open; refused for an empty `projects`. Answers every project the connection is subscribed to.

- Since contract version 1, experimental.
- Params: `SubscribeProjectChangesRequest`
- Result: `SubscribeProjectChangesResult`
- Errors: `1` refused, `2` failed

## stream

### `list_streams`

List every stream the runtime holds, by stream id, with its location and state.

List every stream the runtime holds: its stream id as `stream`, its `display_name`, its `location` — its project directory, its project's UUID as `project` and its stream asset's UUID as `stream_asset`, `null` for a record an earlier runtime wrote — and its state: `running` (playing, or recorded playing and re-loaded playing at the runtime's next start), `stopped` (open with its playback stopped, its graph loaded to read and edit while its node count is set, until `start_playback`), `paused` (open with its playback paused by `pause_playback`, until `resume_playback`), `closed` (its project closed by `close_project`, not loaded, until `open_project`), `preparing` (an action that loads it — an `open_project`, `reload_project` or `start_playback` — is queued or under way on it, named by `action`, on its `step`: `reading_the_graph_documents`, `making_the_venv` or `starting`, `null` while it waits), `stopping` (a `stop_playback`, `close_project` or `remove_project` of its project is queued or under way on it, named by `action`, on the step `stopping`, `null` while it waits), or `failed` (its code, its venv, its load or its start failed, and held stopped from its document when that reads, its graph there to read and edit, until a play or a `reload_project` retries it; implicated in the runtime's last two crashes in a row, and held at a start from its document with none of its node code read until a `reload_project` of its project tries it; or recorded by an earlier runtime, never loaded, with `failed_because` saying to run it again and `remove_project` forgetting it), with the node count of its loaded graph (`null` when it is not loaded), `failed_because`, why a failed stream failed (`null` otherwise), and `capture_devices_whose_access_was_never_asked_for`, each of `camera` and `microphone` that a node of the loaded stream refused because nobody has asked the user for its access, as when the runtime re-loaded the stream on its own at its start (empty otherwise): a `close_project` then `open_project` of its project asks.

- Since contract version 1, stable.
- Params: `ListStreamsRequest`
- Result: `ListStreamsToolResult`
- Errors: `1` refused, `2` failed

## Notifications

### `project_changed`

A change on the feed of a project the connection subscribed to: a transaction applied, an action refused, or media facts read.

- Sent after `subscribe_project_changes`.
- Since contract version 1, experimental.
- Params: `ProjectChangedNotificationParams`
